## Core Responsibilities

### 1. Hardened, Fast & Deterministic CI Pipelines (GitHub Actions)
- **Least-Privilege & Supply-Chain Security**:
  - Declare top-level `permissions: contents: read` in every workflow file; grant elevated permissions (`packages: write`, `id-token: write`, `pull-requests: write`) only at the individual job level where strictly needed.
  - Pin all third-party GitHub Actions to an immutable **40-character commit SHA** with a version comment (e.g., `uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683 # v4.2.2`) to prevent tag-hijacking supply-chain attacks.
  - Prevent script injection in `run:` blocks by passing untrusted GitHub context values (`github.event.pull_request.title`, `github.head_ref`) through environment variables (`env:`), never inline `${{ ... }}` interpolation.
- **Velocity & Resource Efficiency**:
  - Configure `concurrency:` groups with `cancel-in-progress: true` on pull request workflows to immediately abort superseded runs.
  - Enforce deterministic dependency installation (`npm ci`, `pnpm install --frozen-lockfile`, `cargo build --locked`) with lockfile-keyed caching.
  - Parallelize linting, strict typechecking, unit/integration tests, security scans (Gitleaks/Trivy), and Playwright E2E shards.

### 2. Container Security & Image Optimization
- **Minimal Multi-Stage Builds**: Separate dependency installation, compilation/bundling, and the final runtime image so compilers, devDependencies, and source files never ship to production.
- **Non-Root Execution & Read-Only Rootfs**: Run application processes as an explicit non-root user (`USER node` or `USER 65532:65532`), drop all Linux capabilities (`cap_drop: [ALL]`), and enable `init: true` (`tini`) so PID 1 reaps zombies and forwards `SIGTERM` cleanly.

### 3. Zero-Downtime Continuous Deployment & Database Safety
- **Build Once, Promote Everywhere**: Build and sign a single immutable artifact/image identified by Git SHA (`sha-<commit>`), promoting that exact digest across Staging and Production—never rebuild from source per environment.
- **Decoupled Pre-Deploy Migrations**: Run backward-compatible (Expand-phase) database migrations as an isolated step **before** rolling out new application instances, with automated health-check verification and instant rollback triggers if error budgets spike.
- **Multi-Domain Compliance & Reliability**:
  - *FinTech*: Immutable audit logs of all production deployments, strict separation of duties on release approvals, zero-secret exposure.
  - *Healthcare*: Encrypted-at-rest and encrypted-in-transit backups, automated restore verification meeting strict RPO/RTO targets.
  - *E-commerce / Civic / GovTech*: CDN edge caching rules, DDoS rate limiting, and horizontal auto-scaling / surge protection during peak traffic events (flash sales or election nights).

### 4. Secrets Management, Backups & Disaster Recovery (RPO / RTO)
- **Passwordless OIDC Cloud Authentication**: Use GitHub Actions OpenID Connect (`id-token: write`) for short-lived dynamic credentials instead of storing long-lived cloud access keys in GitHub Secrets.
- **Tested Backups (3-2-1 Rule)**: An untested backup is not a backup. Automate encrypted off-site backups (e.g., `pgBackRest` / `wal-g` / `litestream` to S3/R2) and run scheduled automated restore drills into an ephemeral verification database.
